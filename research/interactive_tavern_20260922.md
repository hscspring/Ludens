**是否需要明确目标，还是自由 Roleplay，尚待讨论。** 漏水与账册提供参与契机，不意味着玩家必须完成任务。团队将讨论明确目标、有情境但自选目标、纯自由互动的体验差异。

下一步希望做到“画随话动”：声音、表情和可见动作回应玩家，场景保留行动后果。优先复用已有开源模型；连续动作与场景演化重点探索世界模型，图片编辑、TTS 和轻量动画也可承担部分表现。Joy 支持语音直出，不支持原生语音的模型可搭配 TTS；原生声画若等待过久，也可评估独立语音提前回应。

视频融合先探索固定视角下的短人物反应，再验证人物操作物品；素材分层、遮挡、物品状态和视频衔接都需要实测。玩家操作立即生效，角色动作的状态与画面时机需协调，过时视频不能覆盖新状态。具体方案见团队共识。

## 当前可以做什么

- 点选铁桶、木箱、账册或两条毛巾，在侧栏执行移动、擦水、拧毛巾等动作；选择次序由玩家决定。
- 桶接住水但不修复漏水，搬木箱会带走其中的账册，单独取出的账册不会跟箱子移动；擦水后的毛巾保持湿润，拧过后仍潮湿。
- 和 Cassian 聊天、请求帮助，或观察他会做什么。他通过 Gemini API 提出台词和一个行动意图，行动由相同规则执行。
- 角色回应期间仍可操作。依据旧场景产生的回应不会覆盖玩家的新行动，而会针对最新状态重新生成。
- 在“回看这段经历”中拖动时间线，查看每次实际事件和物品状态。
- 每个浏览器保存自己的会话 ID，刷新可继续；会话本身在服务内存中，服务重启后需要重新开始。

视频接口只在主动请求经历短片时调用 JoyAI，不参与操作流程。Sean 已停止视频模型以使用全部 8 张 GPU 训练；页面通过 `pipeline/tavern/static/settings.json` 将视频入口标为暂停。当前服务不会加载本地模型，也不会自动启动视频后端。短片属于生成式改编，精确经历以时间线为准。

## 代码职责

- `pipeline/tavern/data_model.py`：动作输入与 `TavernWorld`，保存并验证物品事实。
- `pipeline/tavern/api.py`：`TavernSession` 管理每次经历、并发与事件记录；`Cassian` 调用现有 `LLMClient`；`TavernService` 分配独立会话。经历短片仅由独立后台任务请求已有视频接口。
- `pipeline/tavern/router.py`：HTTP 页面、状态、操作与回放接口。
- `pipeline/tavern/static/`：分层场景、点选反馈、角色对话与回看界面。背景经 imagegen 从已选风格编辑为无道具底图，提示词在 `background.prompt.txt`；独立物品使用 SVG 绘制。
- `pipeline/ludens_pipeline.py`：启动交互版。之前的视频原型保存在 `pipeline/video_demo.py`。

## 已验证

最小核心测试：`python -m unittest discover -s tests -p test_tavern.py -v`。两项通过，覆盖物品后果持续、非法动作不改状态、慢 LLM 不阻塞操作、旧回应不覆盖新动作，以及会话隔离。

真实浏览器验证：桌面连续接水、取账册、擦水；Cassian 仍在等待期间基础动作全部返回，之后自主搬走空木箱。刷新恢复进度、时间线回看、390 像素宽手机布局与浏览器会话隔离均通过。本机两次 HTTP 物品操作实测约 3.52 ms、1.16 ms；这不是外网延迟承诺，也不包括角色回应时间。

可选视频测试：提交请求约 5.52 ms 即返回；期间仍可连续操作，回放记录固定在点击生成时，不被后续行动改写。实际视频生成因本地 JoyAI 已被用户停止而连接失败，因此本版尚未完成真实短片生成验证。视频关闭时不影响以上交互测试。
