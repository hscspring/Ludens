# Ludens 场景互动与视频形态产品讨论

更新日期：2026-09-30

## 一、当前讨论的核心

Ludens 当前探索的不是普通聊天产品中增加视频附件，而是一种以可触碰场景为主体的 Roleplay 形态：角色和物品存在于同一个持续空间中，用户既可以通过语言交流，也可以直接点击、观察和移动场景里的内容；角色理解这些行为，并通过文字、声音、表情或身体行动作出回应。

现有 Demo 已经呈现出基本方向：一段人物视频结束后，画面交接为可以继续操作的场景；物品能够被点选和移动，位置可以保存；角色后续回应可以读取用户刚才做过的事情。下一步需要解决的不是单独生成一段更好的视频，而是把以下环节连接成稳定的产品闭环：



```Plain Text
可操作场景
→ 用户触碰、移动或交流
→ 世界立即记录变化
→ 角色理解用户行为
→ 必要时以视频采取行动
→ 视频结束后形成新的可操作状态
→ 用户继续行动
```

当前仍有两个核心问题没有完全弄清：

1. 如何让以视频为重要表现形式的产品保持持续交互，而不是不断进入等待和观看。
2. 当文字、图片和视频同时存在时，如何让视频自然进入体验，并让用户真正愿意观看。

## 二、对产品形态的初步判断



Ludens 不一定是在做“连续生成的视频聊天”，也不只是“互动视频”。更可能的方向是：



> 用户能够触碰一个持续存在的角色世界，而这个世界在重要时刻以视频回应用户。



这里的“持续”不等于视频始终播放，而是三种连续性同时成立：



- **世界连续**：人物、物品、位置和已经发生的事情不会每轮重置。
- **交互连续**：用户可以持续表达和行动，不必为所有反馈等待视频。
- **视觉连续**：视频开始于当前真实场景，结束后留下的新状态能够继续操作。

因此，一个重要原则是：



> 场景保存当前状态，视频表现状态如何发生变化。



如果把视频本身当作世界状态，每生成一段内容都需要依赖不稳定的末帧来延续，人物、物品和空间很容易逐轮漂移。如果由稳定的场景状态承接每轮互动，视频则可以专注表现有意义的动作过程和人物表演。



## 三、一次交互需要区分的四层内容



为了避免文字、视频和场景各自表达不同事实，每次互动都需要先明确四类内容。



### 1. 当前世界



包括人物、物品、位置、外观、关系、记忆，以及已经发生且仍然有效的事情。



例如：



- Cassian 站在柜台后；
- 木箱位于桌面右侧；
- 账册仍在箱内；
- 用户曾主动把箱子移到不会漏雨的位置；
- Cassian 已经注意到了这个行为。

### 2. 用户意图



用户的输入不只有聊天，还可能是：



- 观察人物或物品；
- 移动物品；
- 将物品递给角色；
- 靠近、回避或等待；
- 询问某件事；
- 通过动作表达关心、试探、冒犯或拒绝。

### 3. 事件结果



需要确定这次行为实际造成了什么变化：



- 哪个物品改变了位置；
- 角色是否看见和理解；
- 角色如何解释用户的行为；
- 关系、态度或后续选择是否变化；
- 是否出现新的可观察信息。

### 4. 表现方式



最后才决定使用什么形式表达：



- 场景中的即时变化；
- 文字；
- 语音；
- 表情、姿态或轻动态；
- 新图片或局部特写；
- 一段短视频。

世界中发生的事实应当只有一份，文字、图片、声音和视频只是同一事实的不同表现。



## 四、怎样形成视频形态的持续交互



### 1. 让场景承担主要交互，让视频承担关键过程



用户移动一个普通物品时，物品可以立即在场景中移动，不需要等待视频生成。系统随后再判断角色是否需要介入：



- 角色没有注意：只更新物品状态；
- 角色看了一眼：使用表情或轻动态；
- 角色说了一句话：使用文字或语音；
- 角色走过来并重新移动物品：使用视频表现完整动作。

这样可以保持操作的即时性，也避免每次点击都变成一次生成等待。



### 2. 把视频理解成有边界的事件



早期不必追求任意时刻都能打断和改写视频。可以先把视频定义为一段较短、具有清楚开始和结束的事件：



- 视频开始前，人物和物品状态明确；
- 视频只处理一个主要动作或反应；
- 用户可以跳过或停止观看；
- 视频播放时，与该事件冲突的物品暂时不能再次移动；
- 视频结束后，人物和物品进入明确的新状态；
- 新状态重新开放完整操作。

例如：



```Plain Text
木箱当前位于桌面左侧
→ Cassian 决定把它移回干燥位置
→ 播放接近、搬动和松手的短视频
→ 木箱停留在新的实际落点
→ 用户可以再次点击和移动
```



### 3. 允许等待期间继续体验，但避免状态过期



如果视频根据木箱位置 A 开始生成，而用户等待期间又把木箱移动到位置 B，生成完成的视频就会与当前场景冲突。



早期可以采用以下边界：



- 用户可以继续观察场景和查看信息；
- 与本次回应无关的轻量操作可以继续；
- 正在被角色回应的物品暂时锁定；
- 新的剧情行动进入队列；
- 用户可以取消旧回应，按最新状态重新开始；
- 每段视频明确对应某一次用户行为和某一个场景版本。

持续交互的难点并非让视频无限播放，而是确保每段视频回应的是正确的世界状态。



### 4. 视频结束后必须形成可用的新状态



视频不能只在任意末帧结束。结束时需要明确：



- 人物现在在哪里；
- 是否还接触某件物品；
- 物品实际落在哪里；
- 哪些内容重新可以操作；
- 角色态度发生了什么变化；
- 下一步用户能够做什么。

视频末帧可以成为新状态的来源，但不必强制直接使用。必要时可以通过稳定图片、人物与物品分层、局部补全等方式，形成更适合继续操作的场景。



## 五、文字、图片、语音和视频的分工



### 文字



文字适合承担：



- 快速交流；
- 复杂信息；
- 人物背景和无法直接看见的内容；
- 用户操作的简短记录；
- 不值得为其等待视频的普通回应。

文字不应提前完整描述随后视频里的全部动作、表情和节奏，否则视频只是在重复已经读过的内容。



### 图片和可操作场景



图片不是视频的低配替代，而是当前世界的状态载体，适合承担：



- 显示人物和物品当前所在的位置；
- 提供点击、触碰和移动的界面；
- 表现重要但不需要动作过程的变化；
- 提供物品、伤痕、文字或线索的局部特写；
- 承接视频前后的操作。

### 语音



语音可以在不改变场景的情况下增强角色存在感，也适合在视频尚未准备好时提供较快反馈。但如果视频中包含同一段完整台词，需要避免让用户重复收听。



### 视频



视频更适合承担：



- 人物对用户行为的身体回应；
- 动作发生的过程；
- 目光、停顿、距离和犹豫；
- 语言与真实情绪之间的矛盾；
- 关系变化或重要选择的情绪兑现；
- 结束后会留下新状态的关键事件。

一个基本判断标准是：



> 跳过视频，用户仍然能够理解发生了什么；观看视频，用户会对角色和这一刻产生更丰富的感受或判断。



## 六、用户为什么愿意观看视频



用户愿意观看的最强理由可能不是“这段剧情很好看”，而是：



> 我刚才做了这件事，我想看角色会怎样回应我。



例如：



- 我碰了他的东西，他会不会阻止我；
- 我移动了账册，他有没有注意到；
- 我把物品递给他，他会不会接；
- 我靠近后，他会退开还是留下；
- 我发现了秘密，他还能不能继续装作若无其事；
- 我作出重要选择后，我们的关系会怎样变化。

这类视频具有几个共同特点：



1. 由用户自己的行为触发；
2. 与当前场景中的人物和物品直接连续；
3. 人物表演提供了文字之外的信息；
4. 视频结束后留下新的可操作结果。

### 降低观看成本



为了让用户愿意看，视频还需要满足：



- 时长足够短，早期可优先测试 5 至 15 秒；
- 尽快进入有效动作，不用无意义待机填充时长；
- 用户知道将看到什么；
- 用户知道预计时长；
- 可以跳过、重播、开关声音和字幕；
- 跳过后仍能继续体验；
- 视频出现频率足够克制。

视频入口不宜只写“生成视频”或“观看视频”，而可以明确表达内容：



- 看 Cassian 如何回应；
- 看他重新接住木箱；
- 看他发现账册被移动后的反应；
- 等他走过来；
- 让他演示应该放在哪里。

用户需要先知道为什么值得看，才更可能接受等待。



## 七、可以探索的产品方向



### 方向一：可触碰的角色场景



用户进入一个持续存在的角色空间，可以点击人物、查看和移动物品，也可以自由交流。视频是人物开始行动时的动态阶段，结束后返回新的可操作场景。



核心价值是：用户碰过的世界真的记住了他。



主要风险是场景操作停留在技术展示层面，行为没有人物和剧情后果。



### 方向二：用户行动驱动的反应视频



不追求每轮聊天都有视频，而是优先表现角色对用户行为的反应。例如用户移动角色珍视的物品、把椅子拉近、触碰私人用品或递出重要物件。



这个方向最直接地回答视频为何值得观看，也最能体现 Ludens 与普通图文 Roleplay 的差异。



### 方向三：快速模式与沉浸模式



同一用户在不同时间可能具有不同观看意愿，可以探索两种体验节奏：



- **快速模式**：文字和场景状态立即更新，视频默认不自动播放，用户主动回看。
- **沉浸模式**：关键回应自动进入短视频，文字作为字幕或记录，普通内容仍使用文字。

早期可以把它们作为实验条件，而不是立即设计成正式模式。



### 方向四：以事件而不是消息组织内容



一次事件可以同时包含用户操作、角色台词、短视频、场景状态变化和新的可操作内容。产品不再纠结“一条文字是否配一条视频”，而是判断一个完整事件需要哪些表达方式。



例如：



```Plain Text
用户移动木箱
→ Cassian注意到
→ Cassian走近并检查账册
→ 两人的关系和物品状态变化
```



### 方向五：视频中的轻量互动



早期不必实现任意中途改写视频，可以先尝试：



- 点击人物查看当前情绪；
- 点击物品查看信息；
- 长按暂停观察；
- 在特定节点选择阻止、接过来或让他继续；
- 点击角色正在关注的东西，表达“我也注意到了”。

这些操作可以影响视频结束后的下一步，而不必重写已经生成的后半段。



## 八、表现形式的选择原则

每次事件发生后，可以先判断：



1. 用户是否需要立即看到结果；
2. 是否发生了重要的可见变化；
3. 变化是一个状态，还是一个值得观看的过程；
4. 人物的语气、动作和表情是否提供新增信息；
5. 视频结束后是否会留下新的可操作状态；
6. 用户是否可能愿意为这一刻等待；
7. 当前能力能否可靠完成。

据此选择表达方式：

| 事件 | 更适合的表现 |
|-|-|
| 用户移动普通物品 | 场景即时变化 |
| 角色提供复杂信息 | 文字，必要时配语音 |
| 人物轻微情绪变化 | 表情、姿态或轻动态 |
| 新物品、时间或环境变化 | 更新场景图片 |
| 用户发现局部线索 | 局部特写 |
| 角色完成有意义的身体动作 | 短视频 |
| 关系发生重要转折 | 文字、语音和关键视频组合 |
| 无法可靠保持人物或物品一致 | 保留场景，以文字或已有素材回应 |



## 九、失败和降级同样属于产品设计



错误视频会直接破坏用户对世界的信任，因此系统应该允许选择“不生成这一段”。



可以考虑以下降级方式：



- 模型难以稳定移动某个物品时，先由场景即时完成位移，角色只做观察或说话动作；
- 人物过多时拆分为多个反应，不强行生成复杂群体动作；
- 手部接触和遮挡不可靠时，改用局部特写、声音或视频外状态变化；
- 用户在生成期间改变了目标物品时，取消旧视频或按最新状态重新生成；
- 视频末帧不适合继续操作时，生成或组合一个稳定结束画面；
- 普通对话没有观看价值时，只使用文字和语音；
- 生成延迟超过体验可接受范围时，先完成文字与状态反馈，把视频转为稍后可看的内容。

目标不是让所有事件都视频化，而是在不破坏连续性的前提下，让值得观看的事件获得视频表达。



## 十、建议的验证顺序



### 第一优先：完成一次真实闭环



选择一个角色、一个物品和一个可靠动作，完成：



```Plain Text
用户自由操作
→ 状态保存
→ 角色理解
→ 现场生成短视频
→ 视频准确承接当前状态
→ 视频结束后继续操作
```



例如：



```Plain Text
用户移动木箱
→ Cassian注意到变化
→ 生成5至10秒回应视频
→ 视频从木箱真实新位置开始
→ Cassian完成动作并松手
→ 木箱停留在实际落点
→ 用户可以继续移动或询问
```



这个闭环可以同时检验观看动机、等待时间、动作控制、状态继承和视频交接。



### 第二优先：验证没有视频时场景是否仍然成立



加入角色记忆、物品状态、观察与询问、行为后果、关系变化，以及少量图片和表情更新。判断在不连续生成视频的情况下，用户是否仍愿意停留、行动和追问。



如果场景本身成立，视频会成为增强；如果场景本身没有吸引力，更多视频可能只会带来短暂新鲜感。



### 第三优先：寻找真正值得观看的时刻



可以对照测试：



- 用户主动要求观看；
- 系统低频推荐观看；
- 重要事件自动播放；
- 互动结束后生成回忆视频。

重点观察：



- 哪类事件的播放率最高；
- 用户愿意等待多久；
- 视频是否被完整看完；
- 看完后是否立刻采取下一步行动；
- 用户为什么跳过；
- 用户是否主动要求再次观看；
- 视频是否改变了用户对角色的理解；
- 视频是否增加了继续互动的欲望。

## 十一、仍待讨论的问题



- 视频是默认自动播放，还是始终由用户主动触发？
- 是否需要快速与沉浸两种节奏？
- 视频生成期间允许哪些操作，哪些状态必须锁定？
- 一段视频最合适的长度和等待时间是多少？
- 文字应该在视频前完整出现、只显示台词，还是在跳过后再提供全文？
- 视频中的台词与独立 TTS 如何避免重复？
- 视频结束时，什么程度的视觉跳变用户可以接受？
- 哪些触碰行为能够表达用户态度，而不只是移动物品？
- 用户操作后，角色多快作出回应才仍然被感知为因果关系？
- 自主行动如何增强角色存在感而不打断用户？
- 用户愿意长期回到同一个场景，还是需要多个场景和情境？
- 产品的核心吸引力最终来自角色关系、场景操作，还是视觉表演？

## 十二、当前方向总结



现阶段不宜把 Ludens 简化成“每次互动都生成视频”，也不必立即追求可以任意打断的实时生成世界。



更值得优先探索的是：



> 以持续存在、可以触碰的场景为基础，让用户通过语言和行动表达自己；世界立即记录这些行为，角色理解并作出回应；普通变化即时发生，重要动作和情绪由短视频表现，每段视频都会留下可以继续接触的新状态。



文字负责交流和信息，场景负责状态与操作，图片负责稳定呈现，语音负责存在感，视频负责人物行动和情绪兑现。它们不是相互竞争的输出形式，而是共同服务于一个目标：让用户相信自己正在影响一个真实持续的角色世界。
